# Threat model (Tier A, short form)

Date: 2026-11-17. Code read: origin/main at b1e33bc. Bounded by reading and grep; nothing was executed against hostile input. Tier A has no server, accounts or network entry points, so this covers supply chain, untrusted input files, data rights and the integrity of published claims only.

## Assets

1. Integrity of the published numbers and the claims built on them (README, docs/RESULTS.md, docs/ALPHA_RESULTS.md). This is the main asset: the project's value is evidence.
2. The author's reputation and the honesty of the git history (authorship).
3. The author's laptop and GitHub account (code runs there with the author's rights).
4. Compliance with the Binance Vision Dataset Terms and the MIT license of the repository.

## Actors

| Actor | Motive or cause |
|---|---|
| The author, by mistake | Hand edited numbers, a committed data file, an unpinned upgrade, code drafted by a tool and not fully understood |
| A malicious or compromised package or CI action | Supply chain: code that runs at install or in CI |
| A source of a hostile or broken data file | A corrupted download, a wrong file, a file crafted to exhaust memory |
| A reader who relies on a result | Treats a toy result (for example Sharpe 7.13, README line 86) as a trading result |
| A contributor through a pull request | Public repository; CI runs on `pull_request` (tests.yml line 5) |

## Entry points and trust boundaries

| Entry point | Boundary crossed | Where |

## Top abuse and failure cases

| # | Case | Control today | Gap |
|---|---|---|---|
| T1 | A published number no longer matches the code, by hand edit or drift | Seeds in scripts (examples/showcase.py line 5 docstring; examples/alpha_research.py line 74). Reports carry a "generated by" header (alpha_research.py line 79; showcase.py line 334) | No CI check compares regenerated reports with committed ones. README lines 81 and 82 come from no script. Lacks a control |
| T2 | A real data report derived from Binance files overwrites the committed simulated report and gets committed into the MIT repository without CC BY NC SA notice or attribution | None. The script writes to docs/ALPHA_RESULTS.md (alpha_research.py line 241) and docs/figures (line 29) whatever the data source; the source line is recorded in the report (line 71) | No separate output folder, no .gitignore rule for data or real data outputs (.gitignore lines 1 to 7). Lacks a control. Decision 0002 |
| T3 | Raw Binance zips committed to the repository (hosting and redistribution under terms 4.3 and 4.5) | None found in any commit (checked 2026-11-17) | .gitignore has no `*.zip` or `*.csv` rule. Lacks a control |
| T4 | A malicious or yanked package version installs on the laptop or CI | Few dependencies (two at runtime, pyproject.toml line 12) | No lockfile, no hashes, no audit step. Lacks a control |
| T5 | A CI action tag is moved to malicious code | Actions come from the official `actions` organization | Pinned by tag, not commit (tests.yml lines 14 and 15); no `permissions:` block narrows the token. Partial control |
| T6 | A large or crafted zip or CSV exhausts memory or hangs the loader | None | data.py line 64 reads the first zip member fully with no size cap; line 67 loads every row into Python lists. No schema checks (lines 87 to 113). Lacks a control. Harm is limited to the author's own process |
| T7 | A file with wrong timestamp units (microseconds instead of milliseconds) gives a silently wrong grid | None | data.py assumes milliseconds (lines 7 to 10, 117 to 126). Binance changed SPOT archives to microseconds from 2025-01-01. Lacks a control |
| T8 | A reader uses a price, risk or backtest number for a real decision | README footnote on the toy market maker; docs/ALPHA.md section 10 limitations | No single known limitations section in the README. Partial control |
| T9 | A pull request from a fork runs code in CI | GitHub gives fork pull requests a read only token and no secrets by default (GitHub behavior, not verified on this repository's settings). The workflow uses no secrets | Partial control |
| T10 | Git history keeps naming an AI tool as author, against the working agreement | None. All 10 commits carry AI co author trailers; 6 list the tool as author (checked 2026-11-17) | Rewrite not approved. Recorded as risk R2 and an open decision |
| T11 | A secret ends up in the repository or history | No secret found by grep of the tree in Phase 0 | History not scanned with a secret scanner; no scan in CI. Partial control |

No network calls, shell commands, pickle, eval or exec were found in src, tests or examples (grep, 2026-11-17), so injection and deserialization cases do not apply today.

## Not covered, and why

Access control, authentication, session handling, rate limits, logging and alerting: no service, no accounts (Tier A). Revisit if the tier moves to B.
